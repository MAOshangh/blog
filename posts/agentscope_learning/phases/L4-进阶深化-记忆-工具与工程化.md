## 给 Agent 加上记忆：跨轮对话不健忘
到目前为止，你创建的 Agent 每次对话都是『单次思考』：消息传给它，它回答，然后忘掉。真实应用需要 Agent 记住用户身份、偏好、之前讨论过的结论。AgentScope 用 Memory 机制解决这个问题。

官方 memory 模块提供多种记忆实现，最常用的是 TemporaryMemory（临时记忆，会话内存）和 AssistantMsgMemory。用法极简：创建记忆对象，作为 memory 参数传给 Agent 构造函数。此后 Agent 的对话历史会自动存入记忆，下一轮调用时它能看到之前的交流。

理解记忆的边界很重要：记忆默认是『会话级』的，进程结束即清空（TemporaryMemory 是内存实现）；需要持久化时要用带存储后端的记忆实现，具体以官方文档为准。给 Agent 加记忆后，你的应用从『无状态问答』升级为『有状态助手』——这是从 demo 到产品的关键一步。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.memory import TemporaryMemory
from agentscope.model import DashScopeChatModel


async def main() -> None:
    # 1. 创建记忆：TemporaryMemory 是官方内存型记忆
    memory = TemporaryMemory()

    # 2. 把记忆注入 Agent，之后对话历史自动累积
    agent = ReActAgent(
        name="assistant",
        sys_prompt="你是一个耐心的学习助手。",
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeMultiAgentFormatter(),
        memory=memory,
    )

    # 3. 两轮对话：第二轮 Agent 能回忆起第一轮的内容
    await agent("我叫小明，正在学多智能体系统。")
    reply = await agent("你还记得我叫什么吗？我们在学什么？")
    print(reply.content)


asyncio.run(main())
```

**预期输出**：
第二轮回复中能正确说出『小明』和『多智能体系统』——证明记忆机制生效；如果第二轮回『我不知道』，检查记忆对象是否注入

**操作步骤**
1. 运行代码，确认第二轮能回忆起第一轮的信息
2. 把 memory 参数删掉再跑：第二轮会答不上来，直观感受『无记忆 vs 有记忆』
3. 改用 AssistantMsgMemory 再跑一次，对比两种记忆的行为差异（以官方文档说明为准）

**常见坑**
- 忘了传 memory 参数：Agent 默认无记忆，跨轮对话自然不记得
- 误以为记忆会自动持久化：TemporaryMemory 是内存实现，进程结束即清空
- 多 Agent 各用各的记忆：协作场景要让下游 Agent 看到上游结论，靠消息传递而非各自记忆

**要点**
- Memory 让 Agent 跨轮对话有记忆：memory=TemporaryMemory() 一行注入
- 记忆默认会话级、内存实现；持久化需要带存储后端的实现，以官方文档为准
- 协作记忆靠消息流，单 Agent 记忆靠 Memory，两者分工不同

## 给 Agent 工具：能查天气、能算数、能干活
Agent 只会说话是不够的，真实任务需要它『行动』：查天气、搜资料、调用内部 API。AgentScope 的 ReActAgent 支持工具调用：你用 @tool 装饰器把任意 Python 函数声明为工具，模型在思考后会决定『调用哪个工具、传什么参数』，拿到结果再继续回答。

这是 ReAct（Reasoning+Acting）的真正威力：模型先推理，发现『要回答这个问题，我得先查数据』，于是调用工具，观察结果，再组织回答。官方 create_react_agent 教程有完整示例：定义一个 @tool 函数，把函数名传进 ReActAgent 的 tools 参数。

工具函数要写得『对模型友好』：函数名和 docstring 描述要清楚（模型靠这些决定何时调用），参数名要有意义。这是工具调用的黄金法则——工具是给模型用的 API，接口设计要以模型能理解为准。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.model import DashScopeChatModel
from agentscope.tools import tool


# 1. 用 @tool 把普通函数声明为 Agent 可调用的工具
@tool
async def get_weather(city: str) -> str:
    """查询指定城市的天气，参数 city 为城市名（中文）。"""
    # 此处仅为演示返回固定结果；真实场景可接入天气 API
    return f"{city} 今天晴，25 度，适合学习。"


async def main() -> None:
    agent = ReActAgent(
        name="assistant",
        sys_prompt="你是一个能查天气的助手，需要天气信息时使用 get_weather 工具。",
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeMultiAgentFormatter(),
        tools=[get_weather],  # 2. 把工具列表传给 Agent
    )

    reply = await agent("杭州今天天气怎么样？")
    print(reply.content)


asyncio.run(main())
```

**预期输出**：
Agent 先调用 get_weather('杭州') 工具，再把工具返回的天气信息组织成回答打印出来——可以看到中间出现了工具调用过程

**操作步骤**
1. 运行代码，观察 Agent 是否先调用工具再回答
2. 问一个工具无法回答的问题（如『明天呢』），观察 Agent 的应对方式
3. 自己写一个 @tool 函数（如加法器），让 Agent 用工具算数，体会工具调用闭环

**常见坑**
- 忘了在 sys_prompt 里提示工具存在：模型可能不主动调用
- 工具 docstring 写得太含糊：模型不知道何时该调用，接口要清晰
- 工具函数是普通 def 却 await：@tool 支持 async 函数，调用方会 await；保持 async def 与 await 一致性

**要点**
- @tool 装饰器 + tools=[...] 参数 = Agent 获得行动能力
- ReAct 流程：思考 → 调用工具 → 观察结果 → 组织回答
- 工具即 API，函数名/docstring/参数名要按『模型能理解』的标准设计

## 认识 Agent Skill：设计一个技能包
上一节你学会了给 Agent 工具（Tool），这一节学一个更高级的概念：Agent Skill（智能体技能）。Skill 是 Anthropic 提出的一套方法，用来提升 Agent 在特定任务上的表现：把一个任务的『做法』——指令、脚本、参考资源——打包成一个文件夹，用其中的 SKILL.md 文件描述怎么用。可以把它想成一本『操作手册』：手册本身不干活，但 Agent 遇到对应任务时，会先翻开手册（读 SKILL.md），再按手册里的步骤行动。

Skill 和 Tool 的关键区别要分清楚：Tool 是一个『可调用的函数』，Agent 思考后直接调用它（比如查天气）；Skill 不是工具，Agent 不能直接调用它——Agent 必须先读取 SKILL.md 里的指引，再『按照指引』使用自己已有的工具去完成任务。所以官方文档明确说：Skills are not tools，the agent cannot call a skill directly。一个 Skill 本质上是一段高质量、可复用的『做法说明书』，把提示词工程固化成可插拔的单元。

设计一个 Skill，就是设计它的文件夹。目录结构很简单：一个文件夹 + 一个 SKILL.md。官方要求 SKILL.md 必须包含 YAML frontmatter（name 和 description 两个字段，写在开头的 --- 之间）和正文指令。description 决定 Agent 什么时候选用这个技能（模型靠它判断『这个任务匹配哪个技能』），所以描述要写清楚『这个技能解决什么问题、什么时候用』；正文是给 Agent 看的操作指引，要步骤化、可执行，就像写给同事的工作交接文档。

下面用 Python 代码演示如何创建这样一个技能目录（这也是官方示例的写法）：先建文件夹，再把 SKILL.md 写进去。注意 YAML frontmatter 的格式：--- 开头、--- 结束，里面 name 和 description 各占一行。

```python
import os

# 1. 创建技能目录 sample_skill
os.makedirs("sample_skill", exist_ok=True)

# 2. 写入官方要求的 SKILL.md：YAML frontmatter（name/description）+ 正文指令
with open("sample_skill/SKILL.md", "w", encoding="utf-8") as f:
    f.write(
        """---
name: sample_skill
description: A sample agent skill for demonstration.
---

# Sample Skill

这是一个演示技能。当用户的问题与示例相关时，遵循本文件的指引：
1. 先向用户确认需求细节。
2. 用简洁的中文回答，并给出示例。
"""
    )

print("技能目录已创建:")
for root, dirs, files in os.walk("sample_skill"):
    for name in files:
        print(os.path.join(root, name))
```

**预期输出**：
打印一行『技能目录已创建:』和路径 sample_skill\SKILL.md —— 你的第一个技能包做好了

**操作步骤**
1. 运行代码，确认 sample_skill/SKILL.md 已创建
2. 打开 SKILL.md，对照它的结构：--- 之间的 YAML frontmatter（name、description）+ 正文指令
3. 把 description 改成你自己的技能描述（例如『A skill for writing meeting minutes』），体会描述如何决定 Agent 何时选用
4. 在正文里加一条步骤，模拟扩展一个技能的做法

**常见坑**
- 忘记 YAML frontmatter：SKILL.md 不以 --- 开头的 name/description 开头，注册时可能解析失败或提示词里缺少技能描述
- description 写得太泛：模型无法判断何时该用这个技能，技能就『永远不被选用』
- 把 Skill 当成 Tool 调用：Skill 不是可调用函数，Agent 是通过读取 SKILL.md 再行动，不是直接调用
- 正文写得太抽象：Agent 需要可执行的步骤，『好好回答』不如『先确认需求、再分三步回答』

**要点**
- Agent Skill = 把任务做法打包成文件夹：SKILL.md 里是 YAML frontmatter（name/description）+ 操作指引
- Skill 不是 Tool：Agent 不能直接调用 Skill，而是读 SKILL.md 后按指引行动
- description 决定技能何时被选用，正文决定怎么执行——设计 Skill 就是设计这两段文本

## 加载与使用 Agent Skill：Toolkit 注册 + ReActAgent 集成
设计好技能包之后，要让它真正进入 Agent 的『视野』。AgentScope 通过 Toolkit 类提供对 Agent Skills 的内置支持，相关 API 只有三个：register_agent_skill（从给定目录注册技能）、remove_agent_skill（按名称移除技能）、get_agent_skill_prompt（生成所有已注册技能的提示词文本，可附加到系统提示词）。

使用流程分三步。第一步，创建 Toolkit 实例；第二步，用 register_agent_skill 把技能目录注册进去；第三步，把 Toolkit 作为 toolkit 参数传给 ReActAgent——官方文档明确：ReActAgent 会自动把已注册技能的提示词附加到系统提示词（system prompt）里，让 Agent 知道『我有哪些技能可用、什么时候该读哪本手册』。

官方还允许你自定义提示词的排版：创建 Toolkit 时可以传 agent_skill_instruction（向 Agent 介绍技能是什么的一段开场白）和 agent_skill_template（每个技能的格式化模板，模板里必须包含 {name}、{description}、{dir} 三个占位符）。不传就用官方默认模板，先学会默认用法再自定义。

一个非常重要的前提：使用技能时，Agent 必须能读到 SKILL.md 文件的内容——所以官方文档强调，用技能的 Agent 必须配备文本文件读取工具或 shell 命令工具（这正是上一节 @tool 的用武之地）。把这两节连起来看：Skill 负责『告诉 Agent 怎么做』，Tool 负责『让 Agent 做得到』，二者配合才是完整的技能体系。

下面是官方 task_agent_skill 教程的完整写法（整理为可运行脚本）：创建技能目录 → Toolkit 注册 → 传入 ReActAgent。运行后打印 agent.sys_prompt，你会看到系统提示词里自动多了一段『# Agent Skills』，列出了已注册的技能与它的 SKILL.md 路径。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeChatFormatter
from agentscope.memory import InMemoryMemory
from agentscope.model import DashScopeChatModel
from agentscope.tool import Toolkit


async def main() -> None:
    # 1. 准备技能目录（含 SKILL.md，见上一节）
    os.makedirs("sample_skill", exist_ok=True)
    with open("sample_skill/SKILL.md", "w", encoding="utf-8") as f:
        f.write(
            """---
name: sample_skill
description: A sample agent skill for demonstration.
---

# Sample Skill

这是一个演示技能。当用户的问题与示例相关时，遵循本文件的指引。
"""
        )

    # 2. 创建 Toolkit 并注册技能
    toolkit = Toolkit()
    toolkit.register_agent_skill("sample_skill")

    # 3. 查看生成的技能提示词（可附加到系统提示词）
    agent_skill_prompt = toolkit.get_agent_skill_prompt()
    print("Agent Skill Prompt:")
    print(agent_skill_prompt)

    # 4. 把 Toolkit 传给 ReActAgent：技能提示词会自动进入系统提示词
    agent = ReActAgent(
        name="Friday",
        sys_prompt="You are a helpful assistant named Friday.",
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeChatFormatter(),
        memory=InMemoryMemory(),
        toolkit=toolkit,
    )

    # 5. 验证：系统提示词中已包含技能说明
    print("\nAgent's System Prompt with Agent Skills:")
    print(agent.sys_prompt)

    reply = await agent("你好，请用一句话介绍你自己")
    print("\n回复:", reply.content)


asyncio.run(main())
```

**预期输出**：
先打印 Toolkit 生成的技能提示词（# Agent Skills 段，含 sample_skill 与 SKILL.md 路径），再打印 Agent 的系统提示词——末尾多了一段技能说明；最后是 Agent 的正常回复

**操作步骤**
1. 运行完整脚本，对比 agent_skill_prompt 与 agent.sys_prompt 两段输出，确认技能提示词已自动附加
2. 把 Toolkit 换成自定义模板：Toolkit(agent_skill_instruction='<system-info>...</system-info>\n', agent_skill_template='- {name}({dir}): {description}')，再看输出格式变化
3. 调用 toolkit.remove_agent_skill('sample_skill') 后重新生成提示词，观察技能消失
4. 给这个 Agent 配一个 @tool 文本读取工具（参考上一节），体会『Skill 指引 + Tool 执行』的配合

**常见坑**
- 忘了把 toolkit 传给 ReActAgent：技能注册了但 Agent 的提示词里没有，Agent 根本不知道技能存在
- SKILL.md 缺 frontmatter：技能描述缺失，Agent 无法判断何时选用
- Agent 没有文本读取/shell 工具：Agent 知道技能存在但读不了 SKILL.md，技能形同虚设
- 自定义模板漏了 {name}/{description}/{dir} 占位符：格式化时会报错或输出异常
- register 的路径写错：目录不存在会报错，确认相对/绝对路径正确

**要点**
- 三 API：register_agent_skill / remove_agent_skill / get_agent_skill_prompt，都在 Toolkit 上
- ReActAgent(toolkit=toolkit) 会自动把技能提示词附加进系统提示词，无需手动拼接
- 技能生效的前提：Agent 配有文本读取或 shell 工具；Skill 指引方向，Tool 提供能力
- 自定义模板 agent_skill_instruction / agent_skill_template 可定制提示词排版，模板需含三个占位符

## 多模型接入：换模型只改一行
AgentScope 的模型层是抽象化的：Agent 不直接依赖某个厂商 SDK，而是依赖 model 对象。想换模型，只需替换构造时的 model 参数。官方 model 模块提供 DashScopeChatModel（默认示例用的 qwen）、OpenAI 兼容模型、以及各类 embedding 模型（如 OpenAIEmbedding、DashScopeTextEmbedding）。

接入本地/自部署模型（如 Ollama）通常走 OpenAI 兼容协议：通过 base_url 指向本地服务地址即可，无需改业务代码。这样你可以『开发用本地小模型省钱、上线换云端大模型』，模型切换成本几乎为零。

进阶还常用 embedding 模型做『记忆的向量检索』——把消息内容转成向量，按语义相似度找回相关记忆。这一节只需知道：模型是插件化的，embedding 也是模型的一种；具体接入参数（base_url、model_name）以官方 model 教程为准。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.model import DashScopeChatModel


def build_agent(model_name: str, api_key: str) -> ReActAgent:
    """把模型封装成参数，切换模型时只改调用处"""
    return ReActAgent(
        name="assistant",
        sys_prompt="你是简洁的助手，用中文回答。",
        model=DashScopeChatModel(model_name=model_name, api_key=api_key),
        formatter=DashScopeMultiAgentFormatter(),
    )


async def main() -> None:
    # 换模型 = 换一个参数：qwen-max 换成 qwen-plus 或 qwen-turbo（更便宜更快）
    agent = build_agent("qwen-plus", os.environ["DASHSCOPE_API_KEY"])
    reply = await agent("一句话介绍你自己用的模型")
    print(reply.content)


asyncio.run(main())
```

**预期输出**：
打印一段正常的中文回答；把 model_name 换成 qwen-turbo 再跑，回答质量与速度会有差异——体验模型切换

**操作步骤**
1. 运行代码，把 model_name 依次换成 qwen-turbo / qwen-max，感受成本与质量的取舍
2. 阅读官方 model 教程，找到接入 OpenAI 兼容模型（含 Ollama 本地模型）的写法
3. 了解 OpenAIEmbedding / DashScopeTextEmbedding 的用途：向量化记忆检索

**常见坑**
- model_name 拼写错误：会直接报错或静默降级，以官方模型列表为准
- 本地模型地址写错：base_url 必须能连通，本地模型先 curl 验证再接入
- 误以为 embedding 和 chat 是同一个模型：用途不同，按官方文档分别配置

**要点**
- 模型是插件化的：换模型只改 model 参数，业务代码不动
- 本地模型走 OpenAI 兼容协议（base_url），开发省钱、上线换大模型
- embedding 模型用于向量检索记忆，是进阶能力

## 工程化调优：超时、重试、并发与成本
从 demo 到上线，工程化是必经之路。四个核心维度：

第一，超时与重试。模型调用是网络 IO，必然可能超时失败。为模型配置合理的超时时间与重试策略，避免一次慢请求卡死整条流水线；重试要有上限和退避，防止雪崩。第二，并发与限流。多 Agent 并行（fanout）能提速，但会放大对模型服务的请求压力——注意 API 配额，超限时降低并发或开启队列。第三，成本。模型按 token 计费，控制成本的关键是：选对模型档位（turbo/plus/max）、精简 sys_prompt 与上下文、避免无意义的重复调用。第四，日志与观测。把每个 Agent 的输入输出、耗时、token 用量记录下来，出问题能复盘，也能量化成本。

AgentScope 提供 AgentScope Studio 等可视化工具观察多智能体运行过程，是排查复杂协作问题的重要帮手；超时、重试等参数的配置方式以官方工程化文档为准。工程化的原则一句话：让系统在真实网络环境下『可预期地慢，而不是随机地挂』。

**操作步骤**
1. 给模型调用配置超时时间与有限次重试（参数名称以官方文档为准）
2. 把 fanout_pipeline 的 enable_gather 打开/关闭，观察并发对耗时与限流的影响
3. 在代码里打印每个 Agent 的耗时，估算一次完整流水线的成本量级
4. 浏览 AgentScope Studio 文档，了解可视化调试的入口与能力

**常见坑**
- 无限重试：模型持续失败时重试会放大成本与延迟，必须设上限与退避
- 并发无节制：API 限流（429）时先降并发，再考虑扩容
- 只关注功能不看成本：先跑通，再量化 token 消耗，上线前定预算

**要点**
- 工程四维：超时重试、并发限流、成本控制、日志观测
- 重试有上限有退避；并发超限先降并发；成本靠选档与精简上下文
- AgentScope Studio 用于可视化调试，配置参数以官方文档为准

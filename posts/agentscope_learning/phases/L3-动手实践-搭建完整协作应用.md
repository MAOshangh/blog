**学完你能做到**：独立完成一个「策划-写作-评审」三 Agent 协作应用，掌握从设计到运行的完整流程

**前置要求**：需先完成 L2（掌握 MsgHub 与两种管道）。

## 实战设计：从需求到 Agent 分工
动手前先做设计。以「自动写一篇技术短文」为例，拆成三个职责单一的 Agent：策划（planner）接收主题，输出大纲与要点；写作（writer）拿到大纲扩写成完整文章；评审（reviewer）检查文章是否跑题、结构是否清晰，给出修改意见。

设计要点有三条。第一，每个 Agent 的 sys_prompt 只说自己的职责，不要越界——planner 不写正文、writer 不评审，职责单一才好测试。第二，消息里带上下游需要的上下文：writer 需要 planner 的大纲，所以用 Sequential 管道天然满足『上一步输出传给下一步』。第三，输出格式对齐：reviewer 需要能读懂 writer 的文章，写作 Agent 就要输出纯文本文章而不是无关的废话。

推荐流程：先用 L1、L2 学的 API 把三个 Agent 分别单独跑通（各自能完成自己的那一步），再组装成管道。分而治之，别一上来就写完整流水线——哪一步出问题都能立刻定位。

**操作步骤**
1. 为每个角色写 sys_prompt，明确职责与输出预期（大纲/正文/评审意见）
2. 分别单独创建并测试 planner / writer / reviewer 三个 Agent
3. 确认单个 Agent 的输出格式满足下游需要（如 writer 能读懂大纲）
4. 设计消息流转：主题 → planner 大纲 → writer 文章 → reviewer 意见

**要点**
- 先设计分工再写代码：每个 Agent 职责单一、输出明确
- 先单独跑通每个 Agent，再组装流水线，便于定位问题
- 下游 Agent 需要什么格式的输入，由上游 Agent 的输出决定

## 完整实现：三 Agent 协作流水线（可直接运行）
把设计落成代码：三个 Agent 用同一个 create_agent 工厂创建（只改 name 和 sys_prompt），再用 sequential_pipeline 串联。这是本教程第一份『完整可运行』的项目级代码——它就是官方多智能体协作模式的真实写法，你把主题换成自己的，就能做出第一个自己的多智能体应用。

注意代码里三个细节：sys_prompt 明确写了『只输出……』，这是控制 Agent 行为的惯用手段；formatter 统一用 DashScopeMultiAgentFormatter，保证消息里带 name；最后一个 Agent（reviewer）的输出就是整个应用的最终结果。

跑通后做两个变化实验：一是换主题，二是加一个 Agent（比如校对员），体会『加角色 = 加一个 Agent + 加进 agents 列表』的扩展方式——这就是多智能体框架比单模型 API 强的地方：分工可插拔。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.message import Msg
from agentscope.model import DashScopeChatModel
from agentscope.pipeline import sequential_pipeline


def create_agent(name: str, role: str) -> ReActAgent:
    return ReActAgent(
        name=name,
        sys_prompt=role,
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeMultiAgentFormatter(),
    )


async def main() -> None:
    planner = create_agent(
        "planner",
        "你是策划 Agent：把主题拆成 3-5 个要点的大纲，只输出大纲，不要写正文。",
    )
    writer = create_agent(
        "writer",
        "你是写作 Agent：根据大纲扩写成 200 字左右的短文，语言流畅，只输出文章。",
    )
    reviewer = create_agent(
        "reviewer",
        "你是评审 Agent：检查文章是否跑题、结构是否清晰，给出 1-3 条具体修改意见，只输出意见。",
    )

    result = await sequential_pipeline(
        agents=[planner, writer, reviewer],
        msg=Msg("user", "写一篇介绍多智能体系统的短文", "user"),
    )
    print("最终输出（评审意见）:")
    print(result.content)


asyncio.run(main())
```

**预期输出**：
控制台依次出现三条流水线产物：planner 的大纲要点 → writer 的短文 → reviewer 的修改意见，最后打印『最终输出（评审意见）:』加上 review 内容

**操作步骤**
1. 保存为 content_pipeline.py 并运行，观察三段输出
2. 把主题换成自己感兴趣的方向，重跑验证流水线可复用
3. 新增一个校对 Agent（proofreader）并加入 agents 列表，体会扩展方式
4. 把 reviewer 的意见作为提示词再喂给 writer 一轮，实现『写-评-改』循环

**常见坑**
- 某一步输出为空/答非所问：多半是 sys_prompt 没写『只输出什么』，下游收到脏数据
- 结果太长或太短：在 sys_prompt 里加字数约束（如『200 字左右』）
- 一次性写完整流水线再调：先单 Agent 验证，再串联，出错才找得到是哪一环
- 并发限流：如果加了并行环节报 429，改用 enable_gather=False 或降并发

**要点**
- 完整应用 = create_agent 工厂 + sequential_pipeline 串联，代码即模板
- 控制 Agent 输出靠 sys_prompt 的『只输出……』约束
- 扩展 = 加 Agent 并加入 agents 列表；『写-评-改』循环是评审型应用的基本盘

## 工程加固与调试：超时、日志、可视化
demo 能跑只是第一步，真实使用要面对网络抖动、模型超时、参数错误。养成三个工程习惯：第一，模型调用设置合理的超时与重试策略，避免一次请求卡住整条流水线；第二，打开/记录日志，出问题时能看清每个 Agent 的输入输出与调用链；第三，用 stream_printing_messages 观察运行中的中间消息——它把 Agent 打印的消息转成异步生成器，让你实时看到『卡在哪一步、传了什么』。

调试多智能体系统的心法一句话：先定位到具体 Agent，再把它当单 Agent 调。协作层的问题（消息没传对、格式不对）和单 Agent 的问题（提示词不好、模型输出不稳定）分开排查，效率最高。

AgentScope 还有可视化工具 AgentScope Studio 可以观察多智能体运行过程，大项目调试必备；具体参数与界面以官方文档为准。记住：超时、日志、可视化是默认配置，不是出了问题才补。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.message import Msg
from agentscope.model import DashScopeChatModel
from agentscope.pipeline import sequential_pipeline, stream_printing_messages


def create_agent(name: str, role: str) -> ReActAgent:
    return ReActAgent(
        name=name,
        sys_prompt=role,
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeMultiAgentFormatter(),
    )


async def main() -> None:
    planner = create_agent("planner", "把主题拆成大纲，只输出大纲。")
    writer = create_agent("writer", "根据大纲写短文，只输出文章。")

    # 关闭终端直接打印，改用流式观察，看清每一条中间消息
    for a in (planner, writer):
        a.set_console_output_enabled(False)

    async for msg, last in stream_printing_messages(
        agents=[planner, writer],
        coroutine_task=sequential_pipeline(
            agents=[planner, writer],
            msg=Msg("user", "介绍什么是 Agent", "user"),
        ),
    ):
        print(f"[{msg.name}] {msg.content}")
        if last:
            print("--- 本条消息结束 ---")


asyncio.run(main())
```

**预期输出**：
按消息流实时打印：先是 planner 的输出（name=planner），再是 writer 的输出（name=writer），每条完整消息后跟一行分隔线；中间过程一览无余

**操作步骤**
1. 运行代码，对比与直接 print 最终结果的差异，体会流式观察的价值
2. 在 writer 的 sys_prompt 里故意写一个矛盾要求，运行后从消息流定位问题在哪个 Agent
3. 把 stream_printing_messages 换成普通调用，对比两种调试方式

**常见坑**
- 关闭了 console 输出但忘了用流式读取：会什么都看不到
- 流式消息过多：先观察，定位到问题 Agent 后再单 Agent 复现
- 把 stream_printing_messages 当成普通函数调用：它返回的是 async 生成器，必须 async for

**要点**
- 工程三习惯：超时重试、日志、可视化观察，都是默认配置而非补救
- 调试心法：先定位具体 Agent，再当单 Agent 调；协作问题与单 Agent 问题分开排查
- stream_printing_messages 用 async for 消费，实时看中间消息

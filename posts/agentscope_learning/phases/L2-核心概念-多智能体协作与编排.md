## 用 MsgHub 做广播：一个说话，全体听到
MsgHub（消息中心）解决的是『开会』场景：多个 Agent 聚在一起，谁发言都自动广播给其他人，不需要手动把消息一个个传过去。它是官方 pipeline 模块里的一个 async 上下文管理器，创建时传入 participants（参会者列表）和 announcement（开场公告，进入会场时广播给所有人）。

想象一个产品评审会：Alice、Bob、Charlie 入场，主持人广播『请自我介绍』，三个 Agent 依次发言，每个人的发言其他人都能听到——这就是 MsgHub 的效果。它把『手动传递消息』这件事从你的代码里拿掉了，你只需要在 async with MsgHub(...) 的上下文里让每个 Agent 发言即可。

官方还提供了动态管理：hub.add(agent) 添加新参会者、hub.delete(agent) 移除、await hub.broadcast(msg) 主动广播。注意：新加入的参会者收不到之前的消息。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.message import Msg
from agentscope.model import DashScopeChatModel
from agentscope.pipeline import MsgHub


def create_agent(name: str, role: str) -> ReActAgent:
    return ReActAgent(
        name=name,
        sys_prompt=role,
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeMultiAgentFormatter(),
    )


async def meeting() -> None:
    alice = create_agent("alice", "You're Alice, a product manager.")
    bob = create_agent("bob", "You're Bob, a developer.")

    async with MsgHub(
        participants=[alice, bob],
        announcement=Msg("user", "用一句话介绍自己的角色。", "user"),
    ) as hub:
        # 各说一句，无需手动传消息，发言自动广播
        await alice()
        await bob()


asyncio.run(meeting())
```

**预期输出**：
打印 Alice 与 Bob 各自的一句话自我介绍（两人都能看到对方的话，但因为只各说一句，重点是广播机制生效——可在代码里加 await alice() 后再让 bob 复述 Alice 来验证）

**操作步骤**
1. 把代码保存为 hub_demo.py 并运行，观察两个 Agent 的自我介绍
2. 把 announcement 改成『请 Alice 先自我介绍，然后 Bob 复述 Alice 的话』，再运行
3. 观察 Bob 是否准确复述了 Alice——是则广播机制生效
4. 试一下 hub.add() / hub.delete() 动态管理参会者

**常见坑**
- 忘了 async with：MsgHub 必须作为异步上下文管理器使用
- participants 传错类型：必须是 Agent 实例列表
- 以为新加入的参会者能收到旧消息：add 之后才发言的才听得到

**要点**
- MsgHub = 消息广播中心：async with MsgHub(participants=[...], announcement=...) 进入会场
- 参会者发言自动广播，无需手动传消息
- 动态管理：add / delete / broadcast；新参会者收不到历史消息

## 用 Sequential 管道串联 Agent：流水线
Sequential 管道（sequential_pipeline）解决的是『流水线』场景：上一个人的输出就是下一个人的输入，按顺序执行。典型例子就是『策划 → 写作 → 评审』：planner 产出大纲，writer 拿到大纲写正文，reviewer 拿到正文评审。

官方提供了函数式（sequential_pipeline）与类式（SequentialPipeline）两种写法，功能等价：函数式适合一次性调用，类式适合反复复用（同一个管道换不同输入跑多次）。管道接收两个参数：agents（按执行顺序排列的 Agent 列表）和 msg（第一个输入消息，可以为 None）。

理解这一点很关键：管道本身不做『智能』的事，它只是把『依次 await 每个 Agent 并把上一步的输出传给下一步』这件重复劳动封装起来。你自己写四个 await 也能实现同样效果（官方代码片段 1 就是手动版），管道是它的语法糖——所以先想清楚每个 Agent 输入输出什么，再决定用不用管道。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.message import Msg
from agentscope.model import DashScopeChatModel
from agentscope.pipeline import sequential_pipeline


def create_agent(name: str, role: str) -> ReActAgent:
    return ReActAgent(
        name=name,
        sys_prompt=role,
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeMultiAgentFormatter(),
    )


async def main() -> None:
    planner = create_agent("planner", "你是策划：把主题拆成文章大纲，只输出要点。")
    writer = create_agent("writer", "你是写手：根据大纲扩写成完整短文。")

    result = await sequential_pipeline(
        agents=[planner, writer],
        msg=Msg("user", "写一篇介绍多智能体系统的短文", "user"),
    )
    print(result)


asyncio.run(main())
```

**预期输出**：
先打印 planner 产出的大纲要点，再打印 writer 根据大纲写出的短文——最终 result 是最后一个 Agent（writer）的回复 Msg

**操作步骤**
1. 运行代码，观察两个 Agent 先后输出
2. 调换 agents 顺序（writer 在前），运行看效果差异——理解顺序决定数据流
3. 把 msg 换成你自己的主题，跑通一次完整『策划→写作』

**常见坑**
- agents 顺序搞错：管道严格按列表顺序执行，下游 Agent 会收到上游输出
- msg 传了错误类型：第一个输入用 Msg 或字符串，None 表示让第一个 Agent 自行开场
- 以为管道会自动补上下文：它只传上一步的输出，跨步骤长期记忆需要 L4 的 Memory 机制

**要点**
- sequential_pipeline = 顺序流水线：上一个 Agent 的输出自动成为下一个的输入
- 函数式一次性用，类式 SequentialPipeline 可复用
- 先设计每个 Agent 的输入/输出，再用管道串联

## 用 Fanout 管道做并行：同一问题，多方视角
Fanout 管道（fanout_pipeline）解决的是『集思广益』场景：把同一个输入同时发给多个 Agent，收集所有人的回复。典型用法：同一份代码让架构师、安全工程师、性能工程师分别评审，拿到多视角意见。

它的核心参数是 enable_gather：True（默认）用 asyncio.gather 让所有 Agent 并发执行，适合模型调用这种 IO 密集操作（并行显著提速）；False 则按顺序逐个执行，适合需要确定性顺序或怕并发打爆外部服务的场景。返回值是所有 Agent 回复的列表。

官方提示：MsgHub 和两种管道可以组合——广播做『开会』、顺序管道做『流水线』、扇出管道做『并行分诊』，复杂工作流就是这些基本块的组合。学完这一节，你已经掌握了 AgentScope 协作编排的三板斧。

```python
import os
import asyncio
from agentscope.agent import ReActAgent
from agentscope.formatter import DashScopeMultiAgentFormatter
from agentscope.message import Msg
from agentscope.model import DashScopeChatModel
from agentscope.pipeline import fanout_pipeline


def create_agent(name: str, role: str) -> ReActAgent:
    return ReActAgent(
        name=name,
        sys_prompt=role,
        model=DashScopeChatModel(model_name="qwen-max", api_key=os.environ["DASHSCOPE_API_KEY"]),
        formatter=DashScopeMultiAgentFormatter(),
    )


async def main() -> None:
    architect = create_agent("architect", "你是架构师：评估方案的架构合理性。")
    security = create_agent("security", "你是安全工程师：指出方案的安全风险。")

    msgs = await fanout_pipeline(
        agents=[architect, security],
        msg=Msg("user", "评估这个方案：用消息队列解耦订单与库存服务", "user"),
        enable_gather=True,
    )
    for m in msgs:
        print(m)


asyncio.run(main())
```

**预期输出**：
依次打印 architect 与 security 两个 Agent 的回复（各从自己的专业视角评估同一个方案）；enable_gather=True 时两者并发执行

**操作步骤**
1. 运行代码，观察两个 Agent 从不同视角回答同一问题
2. 把 enable_gather 改为 False 再跑，对比输出顺序是否固定
3. 组合练习：先 fanout 收集两个 Agent 意见，再 sequential 让第三个 Agent 汇总

**常见坑**
- enable_gather=True 时输出顺序不保证：并发执行，靠 name 区分谁说的
- 并发调用注意 API 限流：怕超限就用 enable_gather=False
- 返回的是 Msg 列表：遍历时取 .content 而不是整个对象

**要点**
- fanout_pipeline = 同一输入并行发给多个 Agent，收集全部回复
- enable_gather=True 并发提速；False 顺序执行更可控
- MsgHub（广播）+ Sequential（流水线）+ Fanout（并行分诊）组合出复杂工作流
